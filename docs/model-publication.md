# 厂商分组与模型发布

账号保存上游平台、凭据、真实模型目录与精确模型映射。同一账号可关联多个分组，各关联独立配置启停、优先级和权重。厂商字段用于分组展示与推荐规则；模型库中的厂商归属和价格不再作为模型可用性的前置条件。

分组的 `modelAllow` 是发布规则数组，支持精确名称和任意位置的 `*`，完整名称匹配、忽略大小写，其他标点均为字面字符。空数组表示发布账号支持的全部模型，包括其他厂商的模型。

例如 `deepseek*` 匹配 `deepseek-v5`，`qwen*` 匹配 `qwen4-plus`，`*/qwen*` 匹配 `Alibaba/Qwen4`。这些是名称约定，管理员可以修改；不能据此证明上游模型的真实厂商。别名可以用精确规则单独开放。

新建厂商分组时，后端预填可编辑的家族规则。已有精确白名单保持不变。一次性迁移将有厂商、无显式白名单的旧分组转为厂商家族规则，并保留模型库里已确认属于该厂商的特殊名称。无厂商标记的旧分组保持原策略。未内置的厂商在新建时须显式提供规则。

模型发布取账号目录与分组规则的交集。规则可提前保存，也可在网关离线时保存；尚未被账号支持的名称和通配模式不会生成虚构路由。管理目录保留被发布策略关闭的具体模型，因此可以先同步、配置，再发布。模型目录同步会刷新网关矩阵，不依赖价格库识别新模型。

自定义供应商仍需在账号编辑中「获取模型」并保存选择，或者手动配置上游支持的具体模型。仅修改分组规则不会更新账号的能力白名单，也不会绕过上游权限。厂商出现全新的命名家族时，管理员可直接增加规则，无需修改代码。新模型的价格单独配置。

网关按每个账号自己的模型目录展开调度候选，避免同组账号之间借用能力；精确账号映射先基于本账号目录投影，再应用分组发布规则。客户端全局别名会解析到实际模型后再判断账号能力。

探活候选直接来自分组账号目录，再按发布规则筛选，不依赖模型价格库是否已同步。定时探活只执行管理员选定的具体模型，并从网关矩阵选取实际支持它的启用账号关联。新规则、新模型均不会自动扩大探活范围。

- [账号支持判断与映射](https://github.com/Wei-Shaw/sub2api/blob/0f6671457132425d1b84f3d80536b53e02942424/backend/internal/service/account.go)
